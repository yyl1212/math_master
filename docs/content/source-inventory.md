## ZIP 资料整理流程

1. 获取 ZIP 后先建立原包清单：文件名、来源链接、获取日期、文件大小、SHA-256 和读取状态。原始包保存为本地输入，不直接作为 Go 内容包导入，不提交整个资料库到 Git。
2. 先列包内目录，记录条目路径和格式，再解压到单独临时目录。检查绝对路径、`../`、符号链接及声明展开体积，设置解包数量和体积上限；嵌套压缩包单独登记，不自动递归展开或执行其中脚本。
3. 按实际格式读取 JSON、Markdown、表格、PDF 等材料，保留 ZIP 摘要和包内相对路径，作为每条候选知识点的追溯信息。包内格式未核验前不假定都是可直接导入的 JSON。
4. 用文件摘要识别完全重复的资料；同一知识点不同版本、成立条件和证明不能因标题相同就合并。先记录差异，再核对数学体系和适用范围。
5. 建立“原包 → 条目 → 板块/知识点 → 来源 → 待复核草稿”的映射，生成符合版本化 JSON 契约的原创讲解与路线；经过结构校验和独立复核后发布。

原始 ZIP 和解压资料的体积与正式内容包的 10 MiB 限制分别管理。正式内容包只包含本批次整理出的结构化数据和素材引用，不能把整个 ZIP 嵌入内容字段。私有本地输入目录与临时目录的忽略规则在实施时加入 `.gitignore`。

# 第三阶段方案：可行性与兼容性审查

日期：北京时间2026年10月14日。基线：master `bf8e02c2193ffca1c6534b1991399cacce62ce12`。分支：`codex/page-beauty-plan`。

审查对象为[设计](../specs/2026-10-14-page-beauty-design.md)、[逐页分析](2026-10-14-page-beauty-page-audit.md)、[实施计划](../plans/2026-10-14-page-beauty.md)。本轮是方案审查，非已实现代码审查。采用源码交叉核对、本机合成场景实测与同席第二轮静态复核；没有冒称独立审查者或生产登录验收。

## 1. 审查依据与实际工作

1. 拉取master并确认准确基线；复用已有隔离worktree，新建文档分支。生产当前版本与方案基线相同；本轮未连接生产数据库、未修改生产服务。
2. 枚举全部49个page.tsx及全局状态，核对route、默认导出和原跳转；逐页表覆盖49/49，无漏页。当前23页另有2个学习工作区变体，旧入口为14跳转+12退场。
3. 阅读当前首页/目录、阅读与安全Markdown、学习/笔记/分享、复习会话/比对、认证导航、管理与反馈组件和样式，核对既有状态机边界。
4. 在本机独立PostgreSQL17.11合成库运行现有真实harness与当前前端，采集25个代表状态、双语、三种宽度的150幅基线；比对态显式等待自评按钮出现后增量重采24幅，最终矩阵仍为150。未通过模拟API掩盖真实身份与场景流程。
5. 检查现有CI保护、精确文件摘要和固定兼容前端构建：原workflow末尾job不允许追加其他job；旧fixture没有冻结全局CSS，仍会继承共享样式。
6. 依据W3C公开说明复核对比/重排/目标尺寸；实算现有与候选颜色，普通文字4.5:1阈值不能四舍五入后放行。

合成审阅开始时曾因临时库名不符安全前缀、PostgreSQL初始化临时服务器过早报告socket就绪而未启动。只修正临时配置为测试库前缀和TCP就绪，未改harness或降低保护；成功采集后专属容器和进程已清理。此项不是生产或产品代码缺陷。

## 2. 可行性结论

| 项目 | 证据与结论 | 实施验证 |
| --- | --- | --- |
| 技术栈 | 已有CSS Module、ReactNode槽、原生表单与KaTeX足够，无需新产品依赖 | 类型/构建、同根study样式在各断点的computed style |
| 视觉方向 | 暖白/深绿基底已存在；用户已选安静学术方向 | 逐页前后对照与人工审美判断，不能只靠截图差异率 |
| 手机布局 | 标准夹具223.30px页头，无页面横溢；重组utility可减少分行 | 390普通身份≤184px；320/长名/管理员展开全部可达 |
| 文字可读 | 当前正文14/13px；原muted暖底4.497:1 | study17/16px、新muted暖底5.080:1；实际背景/字号检查 |
| 数据与接口 | 改动可限制在展示组件及CSS，不需要DTO/后端/数据库变化 | 迁移15、API/客户端/命令hook字节不变 |
| 性能 | 不引入字体/图片/库或新请求；少量共享CSS和无状态组件 | 同口径CSS≤+10KiB，代表路由初始JS≤+8KiB |
| 验证环境 | 现有harness可真实构造笔记审批、复习和管理员状态 | T1补齐两类反馈详情；T7新CI覆盖多浏览器 |
| 发布恢复 | 当前与未来候选均为15版数据库，原运维兼容门禁可复用 | 回退只限上一15版；不回14、不改备份政策 |

结论：方案可以在现有架构内实施，无需新后端功能或数据库迁移。性能预算、新样式和Firefox/WebKit运行结果是开发后的门禁，本轮不以设计推断冒充通过。

## 3. 初稿问题与修订

| 级别/问题 | 实际依据 | 修订与关闭条件 |
| --- | --- | --- |
| 阻塞：原frontend workflow不能直接追加视觉job | `study-review-ci.mjs`要求原前缀摘要，并拒绝末尾study_review_verify之后出现新job | 改为独立 `.github/workflows/page-beauty.yml`；原workflow/配置全部不改，T7加新CI与篡改校验 |
| 重要：共用CSS会影响旧兼容前端 | build-legacy复制当前前端，再覆盖固定fixture；manifest不冻结样式 | 删除“旧视觉完全不变”的假设；增加可选study外观和完整原回归，固定fixture字节保持 |
| 重要：直接加新prose类可能被旧手机规则覆盖 | 原markdown含600px字号规则，Next分块CSS顺序不宜作为契约 | 方案明确同根选择器优先级与真实computed style；默认模式不变 |
| 重要：初稿猜测不存在的私人笔记宿主 | 实际为ManagedNotesPage→OwnNoteList、ManagedPersonal→ManagedNoteEditor | 全部改成真实路径，身份/取数宿主保持，不建立重复页面 |
| 重要：误写复习五分类会改变现有产品语义 | UI为due/unplanned/unfinished/all/future，due包含changed | 文档和计划固定原入口、计数与优先级，不另加业务分类 |
| 重要：为手机复制两套表单/表格会影响焦点、id和命令 | 现有受控输入、并发/未知请求保护 | 保留单份交互DOM；表格局部滚动、不删列，长字段组始终挂载 |
| 重要：以改视觉为由提前加载参考或讨论 | 默写未比对不含参考；反馈讨论原本显式加载 | 明确禁止新请求/预取和CSS假隐藏，T3/T4/T5实测边界 |
| 改进：把44px误作WCAG最低标准、把视口当真机 | WCAG目标尺寸最低24px有例外；Playwright视口不是软键盘真机 | 区分项目44px目标与标准；自动、手动缩放及可选真机证据分开 |
| 改进：真机设备条件未知导致新增不可执行硬门禁 | 本机可测锁定浏览器引擎，无法保证拥有iOS设备 | Chromium/Firefox/WebKit为实施门禁；真机可用时抽检、不可用如实标注，不添加设备采购要求 |

上述问题已落到方案、页表和任务；没有通过放宽原断言、更新旧fixture或扩展后端范围来回避。

- 方案每项均有T1—T8拥有任务；A01—A25与26个旧入口均有最终闭环要求。

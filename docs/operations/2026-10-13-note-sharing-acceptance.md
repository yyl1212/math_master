# 笔记优化与审批分享验收记录

本阶段交付知识笔记格式编辑、公式预览、离开保护、本人集中检索，以及申请、审批、撤回修改和重新审批闭环。方案与计划已获用户确认，采用 Native 执行。产品从最新 master `dec8b9e86499e7ba5dfe49961dfda87ce10a7921` 新建 `codex/notes-sharing` 分支；本记录只覆盖隔离验证，正式发布需另行执行备份和部署门禁。

## 功能与兼容边界

- 普通笔记默认私有，每个账户与知识点一份。管理员只能读取已提交的冻结快照。
- 访客列表及直接详情均受最新 10 条有效分享窗口约束；登录用户可以浏览全部有效分享。
- 待审和已分享期间原保存、删除新请求被锁定；撤回后可编辑，重审产生新的提交标识，旧链接不能指向新内容。
- 原保存成功请求可以用原键确认，返回当前本人笔记；分享旧回执不复活已撤回内容。过期审批返回冲突且不自动重发。
- 原学习四状态、完成事实、原私人笔记 DTO 和已有 API 定义保持。新增分享事件不替代学习事件。
- 原 1—13 SQL 迁移逐字节与 master 相同；已有 OpenAPI paths 和 schemas 对象逐项相同。兼容清单仅追加本阶段文件及具体目标摘要，原基线、旧快照及验证命令保留。

源文件主要分布于 `backend/internal/notesharing`、`store/note_sharing_*`、`httpapi/note_sharing_*`、`frontend/src/lib/note-sharing`、`features/notes` 和四个新动态页面。原私人笔记写入仅接入同事务分享锁；原知识阅读页、导航、双语与精确代理按计划接线。

## 执行裁定

1. 为技能脚本识别，任务标题机械改为 `Task N`，正文范围不变。
2. 浏览器历史只保存路由位置数字，保留 Next 原状态，不存笔记正文，也不插入截断前进历史的哨兵项。
3. 根历史监听器先分派当前脏笔记页保护。原局部监听晚于路由处理会丢草稿，已通过单元及真实双视口失败复现和修复验证。
4. 原嵌套 SQL check 在恢复的空搜索路径下失败。恢复工具仅调整经校验的首部会话路径为 `pg_catalog, public`，不改原函数、备份或正文，保持单事务及遇错停止；新增正文保留、非法首部和中途整体回滚测试。额外私有临时 SQL 空间需在恢复时预留。
5. 未发布迁移 14 的正文边界改用等价平铺 AND，避免导出重建后目录表达式改变；只接受单一固定摘要，不添加宽泛兼容摘要。已有本分支临时旧 14 库须重建或完整恢复，生产 master 13 不受影响。
6. 计划中的“撤回可执行”明确指知识不可用。分享 schema 损坏时按方案 §6 所有分享接口拒绝，避免缺事件/回执时提交无审计状态；原私人读取保留，结构修复后恢复操作。

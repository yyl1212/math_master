## 1. 用户目标、已确认约束与本次选择

用户要求面向从零基础到学术前沿的六类人群，以正确的数据、丰富知识和学习路径为优先；知识点包含公理、定理、概念等，可见解锁状态、已学记录并可回顾。界面以英文为主，保留中文术语，文档使用中文。首批实际数学内容仍需 P6 整理与独立复核，Knowledge_JSON 持续更新但不直接成为公开内容或判分依据。

本次将已确认的 P4 学习规则落实到个人学习子系统：
- 已发布讲解允许浏览，个人解锁管理普通检测及路线推进。
- 主动开始、明确完成分别记录；滚动页面、停留计时和检测通过不自动制造阅读完成。
- 节点、诊断、复习检测都使用五个不同有效实例，覆盖全部核心目标，至少四题正确通过。
- 普通后继要求全部准确前置版本具有“完成学习且检测通过”的有效证据；该前置的有效诊断资格可替代。
- 诊断无需事先解锁，只授予被测知识的资格，不替用户完成其他前置知识。
- 创建前三十分钟的答案曝光及最近一次已提交检测的实例排除；排除后重新检查五题覆盖。
- 当前资格与历史解锁分开。普通题库替换不自动推翻正确旧证据；永久撤回即时限制相关证据。
- 路线进度固定版本和分母；新内容不静默改写旧学习记录。

本文新增且已确认的具体选择：个人路线采用明确加入动作；每个账户最多一个进行中正式检测，检测有效期二十四小时；练习最多一个进行中实例；默认不做服务器端草稿答案自动保存；多个可用蓝图由用户按核心目标选择。时间上限用于控制过期记录，界面显示到期时间，不采用限时考试倒计时。这些规则不改变五题四题通过标准。

## 2. 方案比较与推荐

| 方案 | 收益 | 代价 |
| --- | --- | --- |
| 一次交付 P4b 完整闭环，推荐 | 阅读动作、练习、检测、资格、解锁和回顾可以作为同一真实流程验收 | 实施任务需要按依赖拆分；最终必须覆盖所有证据竞争场景 |
| 先练习与检测，再个人进度 | 较早提供题目交互 | 中间交付尚不能准确展示解锁，接口与回归要再次衔接 |
| 先手动进度与地图状态 | 页面变化较少 | 不能满足当前有效资格、诊断和安全判分要求，之后需重做状态来源 |

沿用 Go 模块化单体、Next.js 展示和同一 PostgreSQL，不增加队列、缓存、外部 AI 判分或第二数据库。P5 的反馈工单、批量重评和通知，以及 P7 的部署与生产负载验证保持原分期。

    Evidence --> Learning
    Restriction[知识与题库永久撤回事实] --> Evidence

    Assessment --> DB

Go 独占判分、资格与解锁逻辑。Next.js 只提交用户动作并展示后端结果，不自行生成分数或根据客户端状态授予资格。新增学习者 DTO 逐字段构造，不通过删除答案字段来复用管理员题包、实例、送审或归档 DTO。

## 4. 内容、解锁与学习状态

内容建设状态沿用原公开接口，规划中节点不计作用户未解锁。个人状态按用户、知识稳定 ID、准确版本分别读取：
- 解锁：当前允许进入普通检测，或已有该稳定 ID 的历史授予记录。
- 学习：未学、学习中、已学、待巩固、已掌握。
- 证据：显示学习完成时间、检测时间、知识版本、检测类型及是否仍有效。

状态优先级沿用总体方案：待巩固、已掌握、已学、学习中、未学。“已掌握”来自有效检测通过；普通推进资格还需要同版本明确完成记录。检测先通过、之后明确完成，以及先完成、之后检测通过，两种顺序均可形成普通资格。诊断资格不需要阅读完成。

最近复习失败使展示状态为待巩固；其他仍有效的通过证据不被删除，也不单凭一次复习失败取消已经取得的历史解锁。纠错导致所有通过证据失效时，同样显示待巩固并要求重测。

个人新动作只面向当前有效知识版本；旧版本仅保留摘要与历史，不提供任意知识版本的私有讲解入口。学习动作以一个知识版本为单位，同时固定当时关联的讲解单元和素材引用供追溯；多种讲解角度不是多个独立的必修签到。开始只记录一次首次开始时间，重复开始不制造时长。明确完成需已有该版本的开始记录；重复同一动作幂等。版本更新后创建新版本记录，保留旧完成记录，不能把旧时间复制成新版已学。

## 5. 个人路线与历史解锁

加入路线是带 CSRF 和幂等键的明确 POST。服务器固定当前有效路线 ID/version/SHA、实际内容 publication、按顺序排列的准确知识引用及分母。路线最多一千节点，沿用当前内容快照最多一千知识的边界，不扩大原发布容量。

加入时为根节点、已符合前置的节点及已有诊断资格的节点授予历史解锁。单独学习一个当前默认解锁节点时，开始动作同时保存其首次解锁；普通检测创建也先保存该合法授予。尚未加入或主动开始前，GET 只显示当前允许状态，标明没有个人路线记录，不制造历史授予。

普通通过、完成阅读或诊断通过后，同一事务仅计算当前已发布知识中的直接后继，候选最多一千节点，按全部准确前置版本判断。旧路线仅派生固定节点的进度，不在每次动作中遍历用户全部历史路线或对未发布旧节点新增资格。资格是节点自身证据，不递归伪造对所有祖先的掌握。已授予的稳定知识 ID 不重复授予或删除；事件保留来源知识版本、依据和内容快照。

旧路线不会静默升级。页面显示“New route version available”，用户明确加入新版后产生另一个固定记录；旧版分母和原知识版本不变。进度同时展示阅读完成数、有效检测通过数和历史解锁数，不混成一个虚假的掌握百分比。待撤回节点保留在旧分母并显示不可用及重测说明，不通过移除分母美化完成率；新加入路线只包含当前有效发布节点。

个人地图按当前目录分页叠加个人状态；路线页显示所选固定版本。点击已学知识点默认阅读当前有效讲解，个人历史链接可以查看旧版本学习摘要与准确题目记录。旧版本公开资产不可通过原接口绕过撤回；个人历史素材走新的所有权与固定引用检查。

## 6. 安全题面与练习

题面只包含：尝试内的位置及固定实例身份、知识引用、题型、题干、公开选项 ID/文字、明确数值输入格式、受控素材引用。提交前禁止出现正确选项、正确数值、解析、验证见证、生成参数、作者集合、来源映射、规范私有正文或判分提示。

安全题面及答案结果使用不同具名 DTO。严格 JSON 边界在 Go 和 Node 一致；拒绝额外字段、重复键、非法整数词法、NUL、超限和截断正文。HTML、公式和原创 SVG 继续沿用受限渲染。

练习要求登录且目标知识当前有效；不要求普通路线解锁。没有蓝图仍可提供已审核且关联准确知识的有效练习，不把练习完成当作检测通过。创建选择一个当前可出题实例，优先未见题；重复题允许用于复习，明确提示。

练习只有一次有效作答。选择题只接受展示的选项 ID，数值题复用 P4a 精确有理数解析和判分；格式错误不终结练习，返回固定格式代码，保留输入。合法提交固定原始答案和结果，随后显示经审核解析并记录曝光。也可主动查看答案，此时终结为 revealed，没有作答分数。新一轮练习产生新 ID，旧结果不可改写。

一个账户只有一个进行中练习，切换知识需明确放弃；练习有效期二十四小时。与进行中正式检测重合的实例不能通过练习查看答案，避免先创建检测再打开练习取答案。

## 7. 正式检测、诊断与复习

节点模式要求个人已解锁；诊断允许对当前有效知识直接开始；复习要求该知识已有个人检测或学习历史，其他规则相同。三种模式使用相同审核题源、核心覆盖、五题及四题通过标准。

获取检测选项只返回准确蓝图身份、公开核心目标、就绪状态及可显示原因。题面历史仅在创建并返回安全题面时记录，每用户/实例保存首次见题和最后见题时刻；读取概览、重放创建或刷新同一尝试不制造新的题目次数。一个蓝图可直接选择；多个蓝图显示覆盖目标由用户选择，不将内部 ID 当作产品名称。服务器再次验证所选蓝图属于该知识准确版本且当前发布有效。

创建事务：
1. 取得当前内容与题库 head、准确蓝图和最多一千候选实例。
2. 排除该用户创建前三十分钟内曝光的固定实例或模板，以及该用户最近一次已提交正式检测的全部实例。最近检测按账户全局排序，含三种模式和 affected 终态，非按知识另算。
3. 排除无效、撤回或不满足固定来源的题；优先该账户未见实例。
4. 用最多八个核心目标的位集合与五题状态动态规划，选择五个不同实例并完整覆盖。排序按是否见过、曝光/题面历史和保存的随机种子决定；可行性和实际选出的五题使用同一目标逻辑，不依赖 P4a 缓存 ready。
5. 固定知识、蓝图、实例身份与 SHA、实际两份 publication、规则版本、完整判分依据和题面顺序；只返回安全题面。

无合法五题返回 ASSESSMENT_NOT_READY。仅三十分钟曝光阻塞时可计算最早候选解除时刻并重新验证覆盖后返回 retryAt；最近检测排除不随时间到期，不能给出等待即可解决的虚假时间。不得扩大参数范围、即时生成未经发布实例、重复题凑数或缩小核心目标。

每个账户最多一个 active 正式检测。第二次创建返回已有尝试摘要及固定冲突代码，不能换键无限创建题组；用户可继续或明确放弃。有效区间为创建时刻至到期时刻之前；到期在读取和命令内按数据库时间判定，不依赖浏览器时钟或后台清理任务。只读 GET 派生 expired；创建新尝试时在用户锁内先将已到期 active 记录终结为 expired，再检查唯一性。提交前再次检查数据库时间，不允许因进入事务时尚未到期而在等待后继续授予。

提交一次包含准确五个位置的答案；跳过用明确的 skipped 分支计错。未知选项、数值格式、数量或身份不符均在判分前整体拒绝，不返回局部正确性。合法五题提交后固定结果；四题或五题正确才通过。答案与解析只在终态结果返回，提交前的 GET、SSR、代理错误或缓存不含答案。没有逐题检查检测答案的接口。

## 8. 曝光记录与进行中检测保护

三十分钟排除基于服务器实际准备交付答案的时间，不相信客户端“看过/没看过”声明。记录先于含答案响应提交，网络中断时采取保守排除；这代表可能收到答案，不伪称服务器能证明用户真正阅读。

所有平台含答案入口纳入记录：练习提交/查看答案、检测结果每次读取、编辑工作区与生成预览、冻结审核详情与实例分页、导出可编辑题包以及同键重放的含答案响应。不含答案的列表/成员摘要不记录。模板正文可推导整个有限实例集，因此按准确模板身份/SHA记录整模板曝光；固定题和已生成实例按准确实例身份记录。草稿预览仅对与当前数学身份匹配的实例或模板产生选题排除，不能用同名但不同正文污染资格。

每用户有单调曝光序号，创建检测固定当前序号。返回答案的事务按同一用户顺序推进序号；提交前检查所选五题在创建后是否被该账户通过其他入口曝光。若已曝光，保存原始提交为 affected，不授予资格；本次终态结果自身的曝光发生在有效性判定后，不反过来推翻本次结果。

授权编辑/复核入口仍按原角色和作者隔离规则运行。为答案交付附加内部事务记录，不改变原响应形状；曝光 GET 只记录服务器答案交付事实，不写阅读完成、分数或资格，Cookie/Origin/Fetch-Metadata 规则沿用原边界。

P4b 未配置时，原 P4a 管理功能仍按旧行为工作；学习子系统整体不可用，避免“检测开启但曝光表缺失”。启用后任何曝光写入失败都不能继续返回答案。CLI 为受信任运维工具，不作为学习者 HTTP 入口或可审计的个人检测路径，不把 CLI 操作者身份伪造成平台账户曝光事件。

## 9. 固定结果、当前证据与撤回

提交时重新检查会话、检测资格、准确知识版本、五题身份与 SHA、实际发布批准依据、核心覆盖和所有撤回限制。以下语义分开：
- 普通模板/题目替换：停止新的选题；已提交正确证据按当时 publication 保留，不能因不在当前题库 head 就失效。
- 进行中尝试：普通题目替换但固定数学依据及知识版本未变，可以按旧固定五题提交；准确知识版本已被新版替换时，记 affected 并要求针对新版重测。
- 模板、实例、蓝图或关联知识/单元/素材永久撤回：相关五题证据即时 restricted，不能用于新资格或后继解锁；不足五题仍不得改分母。
- 当前知识版本与前置要求改变：旧版本记录继续存在，但不能冒充新版本资格。
- 已有其他有效通过证据：使用替代证据；不会只因最新一条受影响就忽略其余有效证据。

正常通过固定检测事件。诊断通过直接形成节点资格；普通/复习通过与同版本有效阅读完成组合后形成普通资格，两种动作顺序均支持。同一事务保存原始作答、结果、资格事件、历史解锁以及幂等成功结果。affected 保存原始提交及原因，score/pass 为 null，不按错误答案计失败，也不授予资格。

结果历史的原分数不被撤回改写，当前有效性在读取时从固定依赖和永久撤回事实派生。受影响题目不继续显示错误答案/解析，保留原始作答、已失效结果和说明。P5 后续追加重评结果、修正依据及通知，不改写原作答。

固定证据的依赖索引覆盖五题、模板、蓝图、知识版本、讲解单元与素材 SHA。读取当前资格以及解锁新后继时使用这些事实，不读一个未经核验的缓存 passed 标志，也不等 P5 批量任务先遍历用户。

## 10. 数据实体与不变量

新增迁移 00006_learning_assessment.sql；00001—00005 及旧内容/题库数学版本保持不可变。设计实体如下，实施计划再将 SQL 与接口逐字段固化：

| 实体 | 主键/关联 | 不变量 |
| --- | --- | --- |
| learning_records、learning_events | 用户＋知识 ID/version；事件 UUID | 首次开始、明确完成和固定单元引用可追溯；事件不覆盖 |
| learning_path_enrollments、learning_path_nodes | 用户＋路线 ID/version/SHA | 实际 publication、固定顺序和分母不可变 |
| learning_unlocks、learning_qualification_events | 用户＋稳定知识 ID；资格事件 UUID | 解锁首次来源永久保留；资格关联准确版本及诊断/普通证据 |
| practice_attempts | UUID＋拥有者 | active 只能终结一次；答案与判分后不可改写 |
| assessment_attempts、assessment_items | UUID＋拥有者；位置 1—5 | 封存五题、两份实际 publication、规则与 SHA；提交后不可变 |
| assessment_answers、assessment_results | 尝试＋位置；尝试 UUID | 合法提交必须五项，唯一终态；affected 与通过/失败区分 |
| learning_evidence_dependencies | 证据 UUID＋固定 kind/ID/version/SHA | 可反向定位撤回；同题多引用不重复计证据 |
| learner_answer_exposures、learner_exposure_state、learner_question_views | 用户＋固定实例/模板身份；用户 | lastExposedAt 单向增长；序号单调；题面历史仅用于未见优先，不能由客户端设置 |
| learning_idempotency | 用户＋动作＋UUID v4 key | 同键同输入重放原状态；同键不同输入冲突 |

实践和检测的 active 唯一性、准确位置范围、终态完整性及封存字节/JSON/SHA一致由数据库约束或延迟触发器保护，不仅依靠 Go 判断。记录关联 auth_users，客户端不提交拥有者 ID。另一用户的 UUID、历史素材或分页请求统一按原 NOT_FOUND 边界处理。

个人记录及原始作答在 P4b 不自动删除；未终结尝试到期保留摘要和题面，不再可提交。只需要最后曝光时刻的投影更新不会无限保留每次页面刷新日志；检测保存创建/提交序号和排除依据可审计。账户删除与数据保留政策将独立制定，不在本阶段偷偷增加硬删除。

## 11. 锁、权限与幂等

学习者变更使用 READ COMMITTED，在取得锁后读取固定状态：
1. 账户管理锁 1296127049 的共享模式。
2. 内容锁 1296127048 的共享模式；发布/撤回继续保留原排他模式。
3. 原 managedIdentity 按 UUID 顺序锁用户行，再锁操作者会话，读取数据库时间及凭据/CSRF/角色。
4. 同用户曝光状态、尝试和学习记录行，按固定顺序锁定。
5. 核验、写入，提交前重新检查会话、凭据和权限。

使用 PostgreSQL 17 的 pg_advisory_xact_lock_shared(bigint)，沿用原相同 bigint 锁键；事务级锁随事务结束释放。不同学习者可并发取得共享锁；同一账户由原用户行锁串行化。具体函数及事务语义已核对[官方函数说明](https://www.postgresql.org/docs/17/functions-admin.html#FUNCTIONS-ADVISORY-LOCKS)和[显式锁说明](https://www.postgresql.org/docs/17/explicit-locking.html#ADVISORY-LOCKS)。管理员撤权、发布和撤回与资格授予不能跨过该锁边界。取消、密码改变、会话到期或最后审计/幂等写入失败整体回滚。原管理员写入锁模式和作者 UUID 排序不修改。

原 P4a 答案读事务启用曝光后使用同一共享锁及拥有者顺序，并在返回前核验权限；原答案写事务继续原排他锁，曝光在原事务内追加。不通过再次嵌套调用仓库事务记录曝光，避免锁重入、响应先发和提交分裂。

学习动作、练习创建/作答/查看答案、检测创建/提交/放弃、加入路线均要求原会话、CSRF、有效 learner 角色及 UUID v4 Idempotency-Key。admin/editor/reviewer 不自动获得其他权限，当前账户若有 learner 角色才可使用个人学习接口；强制改密码状态沿用原限制。

超时或取消只表明结果未确认。客户端保留同键、动作和确切输入，提供主动重试；无自动写入重试。重放仍检查当前权限。新增学习者响应保存固定业务结果身份和原成功状态，重新构造当前展示投影；已撤回答案不以持久旧响应绕过限制。原管理员含答案响应保留准确历史正文供审查，重放重新记录曝光，不将学习者隐藏规则用于改写管理员冻结证据。

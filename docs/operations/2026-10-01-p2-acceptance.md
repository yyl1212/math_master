## 独立审查与一次修复

使用全新上下文 gpt-6-astra 进行只读整分支审查，没有重复派审查者。审查最初判定不可合并，提出三项；作者按实际影响将错误响应问题从 Minor 升为 Important，并完成一次修复及完整回归：

1. **数据库隔离漏洞（Critical）**：pgx 查询参数可覆盖路径中的数据库名。离线失败测试首先验证 dbname/database/编码覆盖可穿透旧保护；修复同时覆盖 harness 与共用测试助手。查询仅接受单个 sslmode/connect_timeout，显式设置解析后的 Database，每次物理连接核验 current_database()，再允许迁移或重置。安全测试从 RED 到 GREEN，开发库未受影响。
2. **已打开页面的撤回覆盖（Important）**：旧浏览器测试未提前阅读。新增预加载条件先失败，再补齐真实路线加载、站内知识导航、五种撤回、刷新及产生网络请求的目录/板块导航；两种屏幕全部通过。原网页读取逻辑无需补入缓存绕过。
3. **畸形错误体误判（按实际影响升为 Important）**：旧逻辑把畸形 400/404 当作确定的查询错误/不存在。客户端和代理现将其视为暂时不可用；有效 HEAD 保留无正文语义。两个失败测试修复后绿色，全部前端 22/22。

没有延后的小问题。此记录说明独立审查提出的问题及作者验证结果，不表示数学内容已获独立复核。

## 实施中的决定及代价

以下为执行记录中的全部 Ruling，按发生顺序保留：

- Ruling: 技能任务提取脚本仅识别英文 Task 标题 — 在忽略目录生成同内容标题映射镜像，原中文计划不变 — 风险：镜像过时；每次开始任务重新生成。
- Ruling: 新增 frontend/tests/fixtures.ts 作为跨任务共用完整夹具 — 测试代码复用正式目录字面数据，运行页面不导入此文件 — 风险：夹具与 API 漂移，真实 E2E 再验证。
- Ruling: 新增 path-connections.tsx 客户端观察器 — SVG 根据真实卡片位置绘制，正文和路线主视图仍服务端渲染 — 风险：尺寸观察器不更新时连线错位，E2E 截图及调整宽度验证。
- Task 6: Ruling: 根目录 tests/e2e 显式引用 frontend/node_modules 的 Playwright 入口，并纳入前端 TypeScript 检查 — 依赖只在 frontend 安装，保留计划的测试目录，无重复安装或运行时软链接 — 如果目录布局变动，需要同步测试导入路径。
- Task 6: Ruling: Next.js 流式 notFound 页面允许 HTTP 200 与 noindex，验证可见不可用提示；公开 API 与 SVG 仍严格 404 — 保留计划中的 loading 边界，遵循框架流式响应语义 — 风险：依赖页面 HTTP 状态的站外客户端会遇到软 404，应使用 API。
- Final: Ruling: P3/P4 账户、审核后台、学习记录和资格不在本分支实现 — 已确认分阶段路线，匿名阅读没有进度副作用 — 如果范围判断错误，需要追加完整账户与学习证据阶段。
- Final: Ruling: P7 公网部署和生产容量不在本次实现 — 用户确认范围是 P2，本次只提供本机预览 — 如果范围判断错误，尚不能作为线上验收。
- Final: Ruling: 数学草稿发布资格交由独立数学复核 — 公开内容保持 0，测试只验证技术链路 — 如果判断错误，正式阅读数据仍不可交付，需 P3/P6 复核。
- Final: Ruling: 新增 testutil/connection.go 与 connection_test.go 共用隔离连接保护 — reviewer 确认原测试助手与 harness 有相同覆盖漏洞，统一修复 — 风险：测试配置只接受 sslmode/connect_timeout 查询，额外参数需显式设计后支持。

## 第二轮采用的切换顺序

1. 在目标服务器云防火墙/安全组放行 IPv4 入站 TCP 443，来源 `0.0.0.0/0`；保留 80 用于证书挑战。
2. 先用网关验证外部 443 与可信 TLS，再停止旧站应用写入，捕获一份新的最终快照；本记录中的 17:18 快照已不代表恢复后的最新源站。
3. 保留新机现有数据库作为迁移中间副本，将其改名归档，再创建同版本、同 locale 的空 `math_master_preview` 数据库；禁止在非空目标强制覆盖恢复。
4. 恢复最新快照并逐表核对，重新登记恢复基线，按状态机启动并 production 激活；完整外部验收后才认定迁移完成。
5. 启用每日北京时间 02:00 备份、运行首次备份、恢复演练、站外副本及重启验证。旧站保持停写，避免数据分叉。

真实凭据、数据库清单和备份均保存在私有目录，不进入 Git。

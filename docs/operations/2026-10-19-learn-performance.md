# 我的学习概览性能修复

日期：2026-10-19。基线：`97f3d917ccbc6ee6951752e1f156fba2513e0104`。分支：`codex/learn-page-performance`。用户已确认修复、回归、审查及通过 MR 上线；本记录先登记上线前证据，生产结果另存现场验收记录。

## 问题与原因

用户反馈每次进入“我的学习”均偏慢。线上已有 6,767 条公开知识。只读执行计划显示，概览中未分类统计对每条知识重新顺序扫描主题关联表，合计 6,767 次扫描、约 600,885 次共享缓冲区命中，单条 SQL 实测约 2.12 秒。

主题目录实际只返回名称、数量及空成员列表；它的容器内读取约 241 毫秒。API/Web/数据库没有持续 CPU 饱和。页面还包含网络和身份校验耗时，SQL 测量不代表整页加载时间。

## 已确认方案与可行性

把活跃主题关联按知识 ID 去重一次，再与公开、未删除知识和当前账号的学习状态连接汇总。去重保证多主题知识只计一次，缺少活跃关联仍计为未分类。只读对比覆盖当前生产账号，原查询与候选查询统计相同；候选 SQL 约 18 毫秒、1,568 次共享缓冲区命中。

修改 `backend/internal/store/knowledge_admin_study.go` 的一条统计 SQL；新增 `backend/internal/store/knowledge_admin_overview_performance_test.go`；维护本文及仓库精确兼容库存。

```mermaid
flowchart LR
  Page[我的学习] --> Auth[现有鉴权与只读事务]
  Auth --> Topics[活跃主题关联一次去重]
  Topics --> Counts[按当前账号汇总原统计]
  Counts --> Response[原概览响应]
```

沿用事务前后身份校验、重复读快照、8 秒业务截止以及所有原 DTO。原迁移 1—16、数据库结构、发布、学习写入、内容变更提醒及前端均保持原实现；无缓存或新增接口。生产已固定 PostgreSQL 17.11，支持所用 MATERIALIZED CTE。该兼容性结论纳入独立代码审查。

## 回归证据

- 先写真实 PostgreSQL 测试：万条知识、49,990 条新增活跃关联。原实现超过测试两秒截止而失败；修复后完整概览读取约 45 毫秒，通过同一个测试。夹具构造不计入读取耗时，业务截止仍为 8 秒。
- 三个账号的小规模手工计数与冻结原 SQL 差分通过，覆盖多主题去重、停用关联、无关联、未发布、删除、四种学习状态、账号隔离和空公开目录。
- 继续运行原学习、知识管理、权限、内容变更确认、工具兼容检查及 CI；完整结果与上线后的实际版本、备份和耗时记录以最终验收为准。

生产诊断只输出耗时、执行计划摘要和等价性布尔值，没有复制生产快照、账号凭据或学习记录。按用户既有决定，正式上线备份仅保留在服务器，并验证可恢复性。


## 本机验证与独立审查

原知识管理及学习真实数据库 `^TestManaged` 共40项通过；受影响知识管理、主题学习、鉴权和完整HTTP包通过（HTTP约143秒）；Go全量vet及全部命令构建通过。Node工具全组108项通过，CI批次库存为153项、70/70/13三批，新增测试也被原managed数据库组执行。

当前生产前端使用新Go联调后端，桌面和手机的学习工作区、权限、笔记保留及页码共22项通过。前端代码与依赖未修改。

独立只读审查无Critical/Important/Minor，确认多主题去重、停用关联、账号隔离、原快照事务及原迁移/API兼容性；审查者独立复跑万条完整概览约42毫秒。生产整页耗时、备份恢复及版本切换留待现场验收；原提醒和历史事件查询保持本次单条统计优化范围，不据此宣称其他查询的更大容量性能。

验证中两次环境问题如实保留：Node的`complete content scene accepts one setup slower than the old five-second limit`首次在默认沙箱监听回环端口被EPERM拒绝，相同代码和断言在允许本机网络的命令下108项通过。浏览器首次误把历史`managed-knowledge-study.spec.ts`配到当前前端，旧检索文案、旧内容变更提示及旧关联链接断言失败，已停止并保留产物；按仓库既有配置分别复核当前前端和83文件历史前端，历史前端原10项现已全部通过，不修改断言。相关Next取消RSC流日志不计为发布或测试结果。

## 一、意图与成功标准

建设覆盖零基础、巩固、进阶到研究分享的数学学习网站，优先保证正确性、覆盖与数据量，其次丰富学习路径和页面体验。P1—P5 已交付技术闭环；P6 把已有内容、题库、审核、学习和纠错能力用于可追溯的正式数学材料。首批聚焦“数的认识与表示 → 四则运算 → 分数与小数 → 比例与百分数”，保留另外十五个板块的导航和建设状态。

沿用已确认的最低门槛：至少 30 个已发布知识点、20 个已审核且当前有效的不同题型模板、300 个不同有效实例；首批每个节点至少 10 个有效实例，其中至少 5 个具备检测资格，并存在覆盖所有核心目标的完整五题组合。模板数、原创固定题数、参数实例数分别报告。草稿、技术夹具、重复版本和未完成独立审核的数据不能计入正式数量。

正文与题面以英文为主，保留中文术语对照。讲解、例子、题目和 SVG 原创；资料用于来源核对和数学事实检查，不因被收藏、具有 AI 审查标签或通过结构验证而获得发布批准。

## 二、选择的交付方式

| 方式 | 取舍 | 结论 |
| --- | --- | --- |
| P6a 准备与草稿，P6b 独立复核与正式验收 | 先完成来源处理、首批材料及准确报告，再按实际人员审核逐批发布；每一步可以清楚验收 | 推荐，落实上一轮已确认的顺序 |

## 五、持续更新资料的处理规则

1. 源路径由操作参数提供，不写入业务代码。快照只能写入全新且被忽略的私有目录；原快照不能覆盖。保留原文件、完整 SHA、索引原字节和相对路径，检查安全路径、符号链接、缺失文件、冲突摘要及采集期间变动。读取失败或采集中发生变化时不能产生成功批次。
2. 保留原 schemaVersion=1 快照字段及 snapshotId 的文件字节摘要含义。第三份索引解释属于追加的输入支持；旧一份或两份索引的有效输入仍得到同样主文件选择和错误约束。索引缺失的旧输入不因此失败。详细审查另存版本化 source-report，不用快照摘要单独代表转换策略。
3. 三份索引的声明联合去重，同一路径的矛盾摘要全部保留并隔离，不能以读取顺序覆盖。包更新、章节副本、合并语料与 legacy_id 分别记录；同标题不能自动证明同概念，成立条件或定义约定不同的条目不能合并。
4. 固定批次保存全部原字节不表示来源已合格。source-report 按选定主文件和实际条目记录可用、待核对、排除及理由；有未解决问题的选定来源阻止相关草稿达到 ready，而其他板块的隔离问题不阻止已核验的初等数学批次继续编写。
5. 原始索引中的 instructions、local_save_workflow 等字段只作资料数据，不执行命令，不修改用户源目录。新一批记录新增、修改和缺失；缺失原文件不自动撤回已发布知识。
6. 每个网站条目保存批次摘要、原文件与条目定位、原始出处及作者、资料版本、使用条件、改写与审核依据。使用条件不明时仅作为核验线索，不复制原文或图形。内部 Library 和本地路径仅留在编辑整理记录，公共材料使用可公开出处。

首批只需要现有 JSON 资料。其他 ZIP、PDF 资料的批量适配和全十六板块自动转换不在 P6a 范围，按后续批次单独审查。

## 六、首批路线与原创内容

首批计划三十个节点，按以下主题编写并建立真正的学习前置图；分组顺序用于组织，不直接当作全部前置边。

| 分组 | 节点主题 |
| --- | --- |
| 数的认识与表示，6 个 | 自然数；零；位值；数轴；比较与排序；舍入与估算 |
| 四则运算，9 个 | 加法含义；加法交换与结合；减法含义；加减互逆；乘法含义；乘法性质与分配；除法含义；有余数除法；运算顺序 |
| 因数与分数基础，9 个 | 因数与倍数；整除；分数与单位整体；分数在数轴上；等值分数；约分；分数比较；同分母加减；异分母加减 |
| 分数运算与小数，4 个 | 分数乘法；分数除法；小数位值；分数与小数转换 |
| 比例与百分数，2 个 | 比与比例；百分数 |

Manes 主文件先提供数、运算和分数的事实核对线索；小数、比例和百分数逐项核对并补齐。所需概念不因源库条目缺失而通过复制旧章节凑数；原创编写须记录公开依据、明确条件，并接受实际独立复核。

每节点含准确陈述、适用范围、可检测学习目标、至少两种讲解角度、例子及练习；合适的主题补充反例、常见误区、估算或问题分解。SVG 覆盖需要视觉解释的数轴、位值、等分、分数及比例主题，标注与数学量一致，沿用安全白名单和响应式展示。

已有稳定 ID 对应同概念时新建版本，保留原版本及摘要；新概念新建 ID。正式路线使用新的稳定 ID elementary-foundations，逐个固定知识版本。不能覆盖原十节点草稿或把旧学习记录自动迁移到新版本。目标、题目关联和前置关系在实施计划中锁定并经数学审查。

## 七、题库与数量口径

现有三类有限引擎 rational_arithmetic、rational_comparison、missing_operand，以及原创单选固定题足以组织首批。不增加符号求解或证明自动判定。概念、反例及无法由现有引擎表达的题意采用逐题独立审核的原创单选固定题，不借用不匹配的数值见证。

模板的题意、参数域、约束、解释、知识版本和目标映射一起批准；生成器与校验器保持独立实现。版本变化或只换数字不算新题型。至少二十个模板须有不同的有效学习目标或题意，具体数量由逐节点覆盖矩阵决定，不强制把模板数限制在二十。

编写目标给选题留出余量：每节点尽量准备十五个或更多不同实例；全路线至少三百个不同实例是最低验收门槛。多个节点共享实例时全局只计一次，节点关联必须真的覆盖目标，不能复制覆盖字段凑数。若有限模板参数、排除条件或共享去重造成不足，补充有意义的参数组合或独立固定题。

每个节点明确核心目标与 blueprint，至少五个检测实例之外，还要证明可以选出五个不同实例共同覆盖全部核心目标。计算继续采用准确有理数及既有整数、小数、分数、题面明确的百分数语法；保留分母非零、输入长度、选项唯一、边界与排除组合验证。

静态覆盖不等于任意用户此刻可检测。P4 的进行中尝试、答案曝光冷却及最近一次提交排除仍生效。真实选题同时按实例及模板曝光排除；一题的模板解析曝光可能让同模板全部参数实例在冷却期内不可用。因此每个节点在一次练习后还需有来自其他未曝光模板或独立固定题的完整五题核心覆盖见证；只有同模板十五个参数不满足这一体验验收。不能为了达到此目标削弱曝光规则，必要时增加真正不同的来源。

检测候选必须符合既有 assessment_sources 的准确主知识 ID/版本、blueprint 来源、当前发布/审核/素材和撤回条件。跨节点 coverage 关联不直接算作其他节点的检测候选。验收另验证全新学员首次检测、一次练习后检测及手动重测；多次练习或提交后没有合格五题时显示 ASSESSMENT_NOT_READY，不保证任意次数的立即重测，不降低题数或改动 4/5 通过标准。

## 八、只读验收与质量报告

新增有界的运维 content-audit 命令：操作者显式选择验收数据库、路线 ID 与版本，凭据只从私有环境读取，不默认连接生产。报告只读取，不替代现有管理员、编辑或复核权限。

读取在一个一致的数据库事务中固定目录版本、路线身份及摘要、知识 head、题库 head 和所需审核/撤回事实；沿用现有内容同步、依赖核验和事务预算。提取当前有效候选并复用现有精确验证、FiveQuestionCover 与审核事实核验。来源侧使用明确指定的固定批次和来源报告，校验其与实际正文的身份及摘要映射。无法核验、超预算、引用变化或来源报告不匹配时输出失败或不就绪，不能混合多次读到的发布状态。

只统计该路线至少三十个不同知识 ID 的当前有效成员；报告全站数量与首批路线数量时分开显示。模板和实例按实际身份去重，模板版本不重复计题型，撤回或无有效审批依据的成员不计入合格数量。原有覆盖接口的全站总数不能直接用作 P6 路线达标数。

| 报告部分 | 必需证据 |
| --- | --- |
| 运行与发布上下文 | 报告版本、时间、代码 SHA、目录、路线及两个发布 head 的准确身份与摘要 |
| 来源 | 快照与转换策略版本、所选来源、出处与使用方式、未解决问题和完整率 |
| 正式数量 | 已发布知识、有效批准模板、原创固定题、不同有效实例、重复和排除数量 |
| 逐节点覆盖 | 准确知识版本、目标、blueprint、至少十实例、至少五检测实例及完整五题见证 |
| 内容质量 | 两角度讲解、例子、原创素材核验、独立复核记录及实际未解决问题 |
| 学习验收 | 固定版本阅读、通过与失败、前置不足、回顾、曝光与补测、反馈纠错结果 |
| 结论 | draft_ready、awaiting_review、not_ready 或 accepted；逐项原因，不仅给出总体绿色 |

JSON 为准确机器记录，Markdown 为中文摘要。报告不导出用户作答、密码、会话、内部 Library 链接或自由私有工单正文。隔离随机库的技术夹具报告明确 fixtureOnly，不能作为实际正式数量或人员数学批准证据。

## 九、独立复核与发布步骤

作者先提交固定版本，实际独立复核者检查条件、概念与证明、例子/反例、题意、答案/解析、参数边界、图形、来源和目标覆盖。按现有工作流冻结作者集合、摘要和审核事件；修改后重新送审，不继承草稿或旧版本批准。真实人员的独立性不能只靠为同一作者创建第二个账户证明。

先审核发布知识、学习单元、素材及固定路线，再以准确知识版本准备题库，独立审核并按既有双 head 规则发布。中间缺题时如实显示建设中或检测未就绪，不生成用户资格。分批发布的每次切换均遵守当前 expectedHead、重新认证和撤回规则。

P6b 使用实际审核材料生成验收报告并抽查完整学习路径。数学内容批准未落实时仍可完成 P6a 的工具与草稿技术验收；整体 P6 不宣称完成。正式生产部署、迁移、域名、HTTPS 和备份恢复继续由 P7 单独验收。

| 新来源与验收报告 | 独立的版本化产物与只读运维命令，不改变旧 CLI 输出、HTTP 权限或公开 API |
| 新数学内容 | 新 ID 或新版本，现有草稿与固定记录保留；当前路线显式选取准确版本 |
| 题型与覆盖 | 复用已支持的三类引擎和固定单选；不修改已有摘要、生成、判分或 4/5 规则 |
| 审核与发布 | 复用人员隔离、固定摘要和两侧 head；技术校验不替代数学批准 |
| 存储与前端 | 不新增迁移、不修改 00001—00008；英文界面消费现有数据，不改角色、曝光或资格策略 |

以上兼容性范围已随书面方案获得用户确认。实施若发现需要扩充生成器、改变旧快照摘要含义或运行时接口，应先提出具体兼容方案，不能自行加入本阶段。

## 十二、验证与可行性结论

| 风险或限制 | 已明确的处理与验证 |
| --- | --- |
| 源文件继续变化，旧数量失效 | 不可变批次、两次字节核验、前批差异；本文预检只代表记录时间 |
| 八项摘要差异及新增索引 | 保留两侧摘要与隔离理由；所选 Manes 未命中差异，初等草稿可继续 |
| 主文件和章节重复、条件矛盾 | 记录版本/legacy_id/概念条件，不自动合并；差异有处置依据 |
| 首批不是二十模板均匀覆盖三十节点 | 先固定节点目标矩阵，允许更多有意义模板与原创固定题；逐节点五题见证 |
| 现有引擎不能表达所有概念 | 使用独立审核固定单选，不借机开发新引擎 |
| 全站数量、重复实例或旧版本造成虚假达标 | 按准确路线范围、当前有效身份与审核去重，并保留排除原因 |
| 静态 ready 与实际用户冷却不同 | 核验准确主知识及实际选题条件；模板级冷却后仍有不同来源的五题见证，真实联调首次、一次练习后及再次检测 |
| 数学复核人员尚未落实 | P6a 可交付工具与草稿；P6b 有明确人员和发布门槛，未落实不宣称 accepted |
| 只读统计跨 head 或读取过大 | 一致事务、准确身份、有界读取与失败关闭；真实并发及预算测试 |
| 技术夹具被误当正式内容 | fixtureOnly 与实际批准区分；正式材料以实际人员记录和发布为准 |

设计层面已将范围、输入、审核、数量、运行时读取和兼容边界明确，无需要改变既有判分或发布规则的阻塞性设计问题。来源、独立数学审核和 P7 生产运行条件是明确的后续门槛，尚未在本次文档工作中达成。

实施验证包括：旧快照输入和三索引/冲突/变动负测；内容结构、前置图、来源和 SVG；所有有限参数组合及独立校验反例；旧 CLI/API/迁移保护；未批准、撤回、跨路线重复、head 变化和最大合法报告的真实数据库验证；英文阅读、练习、五题检测、解锁回顾与反馈纠错的双视口联调。用实际门槛验证完整三十节点，不把旧夹具容量数字当首批数据数量。

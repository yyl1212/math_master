# 知识导入自动主题归属

2026-10-08，已确认导入修正。归属在导入知识时自动生成，在用户点击“保存草稿”后随正文保存；后台只需复核、纠正和处理待确认项。自动归类不会自动送审、批准或发布数学内容。

## 用户操作

1. 来源维护人员用同一正式批次捕获实际知识文件、分类及dot精确记录映射，校验摘要，安装含记录索引的私有分类档案。不能只装空来源索引目录后猜测记录归属。
2. 导入工具生成topic-draft文件，自动携带知识ID、具体主题ID、来源引用、来源批次，以及已安装的分类版本。摘要由工具生成，使用者不逐项填写。
3. 内容工作区导入该文件，预览知识及归属，点击“保存草稿”。正文保存成功后自动按当前草稿与归属修订顺序保存候选。
4. 页面显示“已归类／待确认或保存／保存失败”数量。失败时保留候选，点击“重试未保存的归属”；不重复保存正文。网络结果不确定时保留同一输入与幂等键，先确认原写入。
5. 缺映射、冲突或来源未被捕获的知识保留待确认。未完整保存的归属阻止送审；正常校验、数学审核和成对发布流程继续。

## 自动归属规则

- 采用dot明确记录映射及知识记录自带的msc_code/msc_codes，匹配来源ID、原记录ID、实际路径和文件摘要。
- 只能归属已捕获目录中的第三级主主题；不把辅助、其他兜底或父主题当成具体主题。最多16个相关主题。
- dot与记录自带标签不一致时保留待确认。多个明确交叉主题可同时归属，祖先自动汇总。
- 来源引用必须来自同批捕获索引，同一作品家族保持一致；不推断外部作者的平台身份，不把本地“approved”转换成网站批准或学习完成。
- 已明确给出的人工resolutions继续支持修正，已有全量归属导入包保持可读；缺少归属的有效知识也可导入草稿。
- 未明确映射的数学类型仍报告TYPE_MAPPING_REQUIRED，不自动猜成定理或定义；证明思路保持sketch。

## 维护工具接线

`buildImportContext(snapshotDir)`读取并核验捕获副本，返回旧capture形状、节点、准确来源记录索引和dot映射；不改变Go分类归档格式。

`buildDraftInputs({...context,records,legacyCatalogue,taxonomyVersionId})`可省略逐记录resolutions；已明确来源和类型的知识自动生成稳定ID与归属候选，输出packages与issues。taxonomyVersionId使用真实安装结果，随导入包携带。旧包未带该字段时使用工作区当前版本，服务器仍检查实际源批次及准确引用。

网页使用既有正文与主题归属接口，不扩大原HTTP输入、权限或数学冻结正文。多条归属顺序保存，不承诺整个批次跨请求事务；部分失败清楚显示并可幂等重试，不显示虚假的全批成功。

## 本轮验证事实

基线469前端通过。新增自动映射、未映射保留、标签冲突、捕获引用缺失、已安装分类版本，以及网页准确修订保存／不确定结果原输入重试均RED→GREEN。当前472前端与类型/构建通过；真实Go/PostgreSQL双视口8项通过27.7秒，第一归属实际已提交后模拟503，重试沿用同键同输入，最终归属修订2，无重复写入或自动批准。

真实本地第186批样本：279记录，157个类型明确的知识草稿，其中10个明确自动归属、147个待确认；122个类型需要人工映射。私有来源仅生成离线候选，未导入生产或批准数学。结果不表示所有旧30知识已完成精确归类。
